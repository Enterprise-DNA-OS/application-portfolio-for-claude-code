The family has a weaker small-business fit than the industry systems already built.

[Ardoq pricing](https://www.ardoq.com/plans) quotes privately, by application rather than seats. Users are unlimited. Its modules cover visibility, transformation and governance, with optional additions and separately purchased professional services. The public replacement page uses no dollar amount because the vendor's own pricing page gives none. [AU/NZ activation partners](https://www.ardoq.com/activation-partners) establish regional availability, not customer usage.

[Ardoq report export](https://help.ardoq.com/en/articles/43935-how-to-create-a-report) supports Excel and JSON. [The API tutorial](https://help.ardoq.com/en/articles/44146-rest-api-tutorial) documents component `_id` and `name`. The importer supports those fields and operator-supplied mappings for customised reports. No full export payload was available from a customer, so fixtures are explicitly synthetic. The import scope excludes other component types and references.

[Ardoq's agent connection](https://help.ardoq.com/en/articles/415375-using-the-ardoq-mcp-server) and reporting make a blanket claim that the incumbent cannot answer natural-language questions false. The page demonstrates tested queries and ownership, not an invented feature gap. [SAP LeanIX pricing](https://www.leanix.net/en/enterprise-architecture/pricing) is a comparison candidate in this same family, not the next new family. [ClientSuccess pricing](https://www.clientsuccess.com/pricing) now requires a quote. Customer success remains a research candidate, not a queued build.
